# EggCheck — Python + web + Docker

Один веб-сайт с **независимым визуальным анализом** пластиковых лотков для яиц. Работает на Linux VPS в Docker Compose. Сверху AI-панель и видео с зелёными/красными рамками, снизу исходный конвейер.

**Важно:** сайт-симулятор `simulator/index.html` оставлен **без изменений**. Код нейросети не подключается к JS/DOM симулятора, не читает настройки, метки и `window.conveyorLab`. Python получает только JPEG кадр **с разрешённой пользователем браузерной вкладки/окна** и возвращает координаты + вероятности. Это то же разделение, что у физической камеры и конвейера.

## Быстрый запуск на VPS

Нужны Linux (Ubuntu 22.04/24.04), Docker Engine и `docker compose` (Compose V2), желательно >= 2 vCPU, 2–4 ГБ RAM, свободное место для Docker. **Для захвата вкладки через браузер необходим HTTPS**, поэтому нужен домен, указывающий A-записью на IP VPS. Открыть внешние TCP-порты 80/443 (и UDP 443 по желанию).

```bash
git clone https://github.com/foryoucode/eggcheck.git
cd eggcheck
cp .env.example .env
nano .env
# замените eggcheck.example.com на свой домен
# затем ОДНА команда для запуска:
docker compose up -d --build
```

Открой `https://ваш-домен`. Caddy сам получает TLS-сертификат через Let's Encrypt/ZeroSSL, если DNS и порты настроены правильно. Посмотреть логи: `docker compose logs -f --tail=100`. Обновить: `git pull && docker compose up -d --build`. Выключить: `docker compose down`.

Если домена пока нет, можно для проверки UI в `.env` указать `SITE_ADDRESS=:80` и открыть `http://IP_СЕРВЕРА`. **Но захват браузерной вкладки в таком режиме не заработает**: современные браузеры требуют защищённый контекст (`https://` или `http://localhost`). Если есть SSH-доступ, для теста можно пробросить порт и открыть `http://localhost`.

## Как работать

1. Открой сайт. Исходный конвейер виден внизу страницы; можно нажать **«Открыть конвейер отдельно»** для отдельной вкладки, чтобы было удобнее захватывать только его.
2. В верхней AI-панели нажми **«Подключить вкладку / окно»**. В системном окне браузера выбери вкладку с конвейером. Это явное разрешение на экранный захват, никаких внутренних данных не передаётся.
3. На превью выдели **только камеру с движущимися лотками**, без панели настроек и подписей.
4. Наблюдай верхнюю картинку — Python возвращает рамки (зелёная = норма, красная = вероятный брак). Порог можно регулировать. При скролле/перемещении источника выдели область заново.

Рекомендация: используй отдельную вкладку с конвейером и выбери её как источник, иначе захват своей же AI-панели может давать визуальную рекурсию. Система не снимает экран без явного согласия и не подключает камеру VPS автоматически.

## Архитектура

```text
Browser: /simulator/ (original, unchanged HTML)
              │    pixels only via getDisplayMedia
              ▼
Browser: ROI crop of tab/window → JPEG POST /api/analyze
              │
              ▼
VPS: FastAPI + OpenCV (boxes) + trained NormalBank/PyTorch MLP (quality)
              │
              ▼
Browser: overlay boxes on EXACT received video frame in upper panel
```

`backend/` **не импортирует** исходный HTML и не знает ни о каких типах брака из генератора. Обучение первой модели было на 40 визуально размеченных синтетических изображениях, показатель перекрёстной проверки 36/40 не является промышленной точностью. Это MVP, мелкие трещины и нестандартное освещение могут давать ошибки. Метка «норма» относится к целому лотку, **не к точному месту дефекта**.

## Репозиторий

- `frontend/`: AI-панель, браузерный захват, отображение рамок.
- `simulator/index.html`: исходный симулятор (не менять).
- `backend/`: независимая обработка пикселей и FastAPI.
- `models/`: обученная модель и банк хороших изображений.
- `Dockerfile`, `docker-compose.yml`, `Caddyfile`: VPS + HTTPS.
- `.github/workflows/ci.yml`: проверка сборки на GitHub.

`/api/health` — проверка здоровья. `POST /api/analyze` — только JPEG/PNG-байты до 2.5 МБ, размер кадра не более 1600px по стороне. Не публикуй демонстрационный API на крупную аудиторию без ограничения запросов и аутентификации. Для личного теста можно дополнительно ограничить доступ к VPS по IP/VPN.

## Что делает GitHub Actions

Проверяет Docker Compose, собирает образ и проверяет загрузку модели при `push`. **Сам GitHub Actions не подключается к твоему серверу:** чтобы делать автоматический деплой на каждый push, понадобятся безопасно настроенные секреты SSH или self-hosted runner. Для ручного обновления VPS уже достаточно `git pull && docker compose up -d --build`.
